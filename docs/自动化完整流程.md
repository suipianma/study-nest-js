## **一、先理解整体在干什么**

前后端两个 GitHub 仓库 → GitHub Actions 构建镜像 → Docker Hub → 本机/服务器用 Docker 更新。

你的项目不是「一个仓库」，而是**两个独立仓库**：


| **仓库** | **GitHub 地址**             | **构建出的镜像**                       |
| ------ | ------------------------- | -------------------------------- |
| 后端     | `suipianma/study-nest-js` | `suipianma/study-nest-js:latest` |
| 前端     | `suipianma/admin-web`     | `suipianma/admin-web:latest`     |


**完整链路：**

你改代码 → git push main

```
↓
```

GitHub Actions 在云端自动运行（不用你本机构建）

```
├── 后端仓库：构建 NestJS 镜像 → 推到 Docker Hub

└── 前端仓库：先 npm build 检查 → 再构建 Next.js 镜像 → 推到 Docker Hub

↓
```

本机/服务器执行 docker compose pull → up -d

```
↓
```

浏览器访问 [http://localhost:3001（前端）](http://localhost:3001（前端）) / [http://localhost:3000（后端）](http://localhost:3000（后端）)

**关键点：**

- **CI（构建）**在 GitHub 云端完成，你不需要在 push 时本机开着 Docker。
- **CD（更新运行中的容器）**需要你在本机手动 `update.ps1`，或装 Self-hosted Runner 自动 pull（可选）。

## **三、配置 Docker Hub（只做一次）**

GitHub Actions 需要**有权限往 Docker Hub 推镜像**，不能直接用登录密码，要用 **Access Token**。

### **步骤**

1. 打开 [https://hub.docker.com](https://hub.docker.com/) → 登录
2. 右上角头像 → **Account Settings**
3. 左侧 **Security** → **Personal access tokens**
4. 点 **Generate New Token**
  - Description：填 `github-actions`
  - Permissions：选 **Read & Write**（或至少 Write）
5. 点 **Generate**，**立刻复制** token（只显示一次，丢了要重新生成）

记下两样东西：


| **名称**         | **值**         |
| -------------- | ------------- |
| Docker Hub 用户名 | `suipianma`   |
| Access Token   | 刚复制的那串（当作密码用） |

## **四、配置 GitHub（两个仓库都要配）**

下面两个仓库的 **Secrets 完全相同**；**Variables 各配各的**。

---

### **4.1 配置后端仓库** `study-nest-js`

#### **打开位置**

1. 浏览器打开：[https://github.com/suipianma/study-nest-js](https://github.com/suipianma/study-nest-js)
2. 顶部 **Settings**（仓库设置，不是个人设置）
3. 左侧 **Secrets and variables** → **Actions**

#### **添加 Secrets（敏感信息）**

点 **Secrets** 标签 → **New repository secret**，逐个添加：


| **Name**          | **Secret 值**                  |
| ----------------- | ----------------------------- |
| `DOCKER_USERNAME` | `suipianma`                   |
| `DOCKER_PASSWORD` | 上一步 Docker Hub 的 Access Token |


#### **添加 Variables（非敏感配置）**

点 **Variables** 标签 → **New repository variable**：


| **Name**              | **Value** | **说明**                             |
| --------------------- | --------- | ---------------------------------- |
| `ENABLE_LOCAL_DEPLOY` | `false`   | 先设 false；装好 Runner 后改 `true` 可自动更新 |
| `ENABLE_SSH_DEPLOY`   | `false`   | 没有远程服务器就保持 false                   |


#### **后端会跑什么 Workflow**

push 到 `main` 后触发 **Backend CI/CD**（文件：`.github/workflows/ci-cd.yml`）：

1. 构建 `suipianma/study-nest-js:latest` 并 push 到 Docker Hub
2. 若 `ENABLE_LOCAL_DEPLOY=true` 且本机装了 Runner → 自动 `docker compose pull && up -d`

---

### **4.2 配置前端仓库** `admin-web`

#### **打开位置**

1. [https://github.com/suipianma/admin-web](https://github.com/suipianma/admin-web)
2. **Settings** → **Secrets and variables** → **Actions**

#### **添加 Secrets（与后端相同）**


| **Name**          | **Secret 值**         |
| ----------------- | -------------------- |
| `DOCKER_USERNAME` | `suipianma`          |
| `DOCKER_PASSWORD` | 同一个 Docker Hub Token |


#### **添加 Variables**


| **Name**          | **Value**               | **说明**           |
| ----------------- | ----------------------- | ---------------- |
| `PUBLIC_API_BASE` | `http://localhost:3000` | 构建前端镜像时写入 API 地址 |


> ***重要：** 前端是 Next.js，*`NEXT_PUBLIC_`* *在**构建镜像时**就写死了。*  
> *本机 Docker 部署用* `http://localhost:3000` *即可。*  
> *以后有公网服务器，改成* `http://你的服务器IP:3000` *再重新 push 前端。*

#### **前端会跑什么 Workflow**

push 到 `main` 后触发 **两个** Workflow：


| **Workflow 名称**                 | **文件**                            | **作用**                                 |
| ------------------------------- | --------------------------------- | -------------------------------------- |
| **Next.js CI**                  | `.github/workflows/workflows.yml` | `npm ci` + `npm run build`（检查能否编译）     |
| **Build And Push Docker Image** | `.github/workflows/docker.yml`    | 构建 `suipianma/admin-web:latest` 并 push |

### **验证 Actions 是否成功**

1. 打开仓库 → 顶部 **Actions**
2. 应看到绿色 ✓ 的运行记录
3. 若红色 ✗，点进去看哪一步失败：
  - `denied` / `unauthorized` → Secrets 用户名或 Token 错了
  - `build failed` → 代码编译错误，先本地 `npm run build` 修
4. 到 Docker Hub 确认镜像存在：
  - [https://hub.docker.com/r/suipianma/study-nest-js](https://hub.docker.com/r/suipianma/study-nest-js)

`deploy/.env` **不要提交到 Git**（含密码）。

## **七、日常开发 → 更新 Docker 的标准流程**

这是你以后最常用的循环。

### **场景 A：只改了后端**

cd study-nest-js

*# 改代码...*

git add .

git commit -m "fix: xxx"

git push origin main

1. 打开 [https://github.com/suipianma/study-nest-js/actions](https://github.com/suipianma/study-nest-js/actions) ，等 **Backend CI/CD** 变绿
2. 本机更新容器：

cd study-nest-js

.\deploy\update.ps1

### **场景 B：只改了前端**

cd admin-web

git add .

git commit -m "feat: xxx"

git push origin main

1. 等 **Next.js CI** 和 **Build And Push Docker Image** 都变绿
2. 本机更新（compose 在后端仓库）：

cd study-nest-js

.\deploy\update.ps1

### **场景 C：前后端都改了**

*# 分别 push 两个仓库*

cd study-nest-js && git push origin main

cd ..\admin-web && git push origin main

两个 Actions 都成功后，**只执行一次**：

cd study-nest-js

.\deploy\update.ps1

### `update.ps1` **实际做了什么**

docker compose pull    ← 从 Docker Hub 拉最新 latest

docker compose up -d   ← 用新镜像重启容器

docker compose ps      ← 看运行状态

## **八、可选：push 后自动更新（Self-hosted Runner）**

不想每次手动 `update.ps1`，可以在**跑 Docker 的那台 Windows 电脑**装 Runner。

### **安装步骤**

1. 打开 [https://github.com/suipianma/study-nest-js/settings/actions/runners](https://github.com/suipianma/study-nest-js/settings/actions/runners)
2. **New self-hosted runner** → 选 **Windows** → 按页面命令安装
3. 确保本机已有 `study-nest-js\deploy\.env`
4. 仓库 **Variables** 里把 `ENABLE_LOCAL_DEPLOY` 改成 `true`

之后：**只要 push 后端**，Actions 会自动在本机 `docker compose pull && up -d`。

> ***注意：** 只 push **前端** 时，后端 workflow 不会跑，Runner 不会自动 pull 前端镜像。*  
> *前端更新后仍需手动* `.\deploy\update.ps1`*，或再 push 一次后端触发 redeploy。*

## **十、常见问题**


| **现象**                               | **原因**               | **处理**                                                 |
| ------------------------------------ | -------------------- | ------------------------------------------------------ |
| Actions 报 `denied: requested access` | Docker Secrets 错     | 检查 `DOCKER_USERNAME` / `DOCKER_PASSWORD`（Token 不是登录密码） |
| 前端页面调不通 API                          | `PUBLIC_API_BASE` 不对 | 在 admin-web Variables 改地址 → 重新 push 前端                 |
| 浏览器 CORS 报错                          | 前后端地址不一致             | `deploy/.env` 里 `CORS_ORIGIN` 必须等于浏览器访问前端的地址           |
| `docker compose pull` 很慢             | 网络                   | 正常；或配置 Docker 镜像加速                                     |
| 3000/3001 端口被占用                      | 本地还在跑 `start:dev`    | 关掉 dev 进程，或改 `deploy/.env` 的端口                         |
| push 了但 Actions 没触发                  | 没 push 到 `main`      | workflow 只监听 `main` 分支                                 |
| Actions 里还是旧 workflow 名              | 本地 workflow 没 push   | 把 `.github/workflows/` push 上去                         |

## **十二、建议的操作顺序（第一次完整走一遍）**

1. Docker Hub 创建 Access Token
2. **两个 GitHub 仓库**都配好 Secrets（+ 前端 Variable）
3. 两个仓库 push workflow 到 `main`
4. Actions 全绿，Docker Hub 能看到两个 `latest` 镜像
5. 本机 `.\scripts\setup-deploy.ps1` 启动栈
6. 打开 [http://localhost:3001](http://localhost:3001/) 验证
7. 改一行代码 → push → 等 Actions → `.\deploy\update.ps1` → 刷新页面验证
